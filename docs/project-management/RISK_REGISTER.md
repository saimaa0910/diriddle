# Risk Register — `diriddle`

Tracks security, privacy, operational, legal/compliance, and solo-developer delivery risks across `diriddle`.

| ID | Category | Risk Description & Evidence | Likelihood | Impact | Severity | Mitigation Strategy | Owner | Linked Issue(s) |
|---|---|---|---|---|---|---|---|---|
| **RISK-001** | Security | **Hardcoded `'dev-secret'` JWT fallback**: If `JWT_SECRET` is missing in deployment, tokens are signed/verified with `'dev-secret'` (`auth.service.ts:215,235`, `jwt.strategy.ts:16`, `community.gateway.ts:37`). | Medium | Critical | **Critical** | Fail fast at NestJS bootstrap if `NODE_ENV === 'production'` and `JWT_SECRET` is unset or `< 32` chars. | Solo Dev | `DIR-008` |
| **RISK-002** | Security | **Expired Admin Roles Remain Active**: `RolesGuard` (`common/guards/roles.guard.ts:18-38`) checks `user.adminRole.role` without verifying `adminRole.expiresAt > now()`. | Medium | High | **High** | Enforce `expiresAt` check in `RolesGuard` and add unit/e2e tests for expired admin roles. | Solo Dev | `DIR-009` |
| **RISK-003** | Privacy | **Reporter Identity Exposed to Moderators**: `AdminService.getReports()` (`admin.service.ts:70`) returns raw `reporter_id` (`userId`), violating anonymity isolation. | High | High | **High** | Strip `reporter_id` from standard moderation DTOs; restrict identity correlation to `TRUST_SAFETY_LEAD` with `AuditLog`. | Solo Dev | `DIR-010` |
| **RISK-004** | Compliance / Safety | **18+ Age Gate Bypass on Write APIs**: `POST /v1/posts` (`posts.controller.ts:39`) and `POST /v1/posts/:id/comments` (`comments.controller.ts:48`) do not check `user.ageVerified === true`. | High | High | **High** | Add `AgeVerifiedGuard` on all content creation/reaction/community-join endpoints and verify in E2E tests. | Solo Dev | `DIR-012` |
| **RISK-005** | Privacy / DPDP | **Incomplete Account Deletion Scrubbing**: `UsersService.deleteAccount()` (`users.service.ts:93-125`) soft-deletes `User` but leaves authored `Post`/`Comment` rows, `AdminRole`, and active JWTs intact. | Medium | High | **High** | Transactional deletion scrubbing/anonymizing posts & comments, revoking sessions/tokens, and deleting device tokens. | Solo Dev | `DIR-014` |
| **RISK-006** | Security | **Mocked Auth & Dev OTP `123456`**: No Supabase Auth integration (`auth.service.ts:239-245`); dev OTP `123456` accepted in all non-production environments; Admin login mocked client-side (`api-client.ts:183-225`). | High | Critical | **Critical** | Integrate real Supabase Auth OTP + Redis rate limiter, gate dev OTP strictly behind `ALLOW_DEV_OTP=true && NODE_ENV === 'development'`, and wire real Admin RBAC login. | Solo Dev | `DIR-011`, `DIR-007` |
| **RISK-007** | Security | **XSS Token Exposure in Web `localStorage`**: Both Expo Web (`storage.ts:13-66`) and Admin (`api-client.ts:39-67`) store Bearer JWTs in `localStorage`, and Admin lacks Next.js `middleware.ts` server guard. | Medium | High | **High** | Move Admin to HttpOnly Secure SameSite cookies + Next.js `middleware.ts`; harden CSP headers and short-lived access tokens for Web. | Solo Dev | `DIR-044`, `DIR-045` |
| **RISK-008** | Security / Anonymity | **Author Block Broken Without Exposing `userId`**: Mobile `app/post/[id].tsx:80` checks `post?.author_user_id` (absent in real API) — tempting developers to expose `userId` to fix it. | High | High | **High** | Add `POST /v1/blocks/by-content` (`{ target_type, target_id }`) so the server resolves and blocks the author without ever returning `userId`. | Solo Dev | `DIR-036` |
| **RISK-009** | Quality / Reliability | **CI & Tests Run Only In-Memory**: `ci.yml` sets `DEV_IN_MEMORY=true` and `0` tests run against real PostgreSQL/PostGIS/Redis, risking production SQL/Prisma regressions. | High | High | **High** | Add real PostgreSQL + PostGIS + Redis integration job in CI running `prisma migrate deploy`, `seed.ts`, and SQL/constraint tests. | Solo Dev | `DIR-047` |
| **RISK-010** | Operations | **Zero Observability & Error Alerting**: No Sentry, OpenTelemetry, or structured JSON logging exists; production crashes and moderation SLA breaches would go unnoticed. | High | High | **High** | Integrate Pino structured JSON logging, Sentry SDK (with PII scrubbing), and health/latency alerts before Beta/RC. | Solo Dev | `DIR-058` |
| **RISK-011** | Operations | **No Production IaC or CD Pipeline**: AWS Terraform/CDK manifests and `deploy-production.yml` do not exist; manual cloud setup risks misconfiguration and downtime. | High | High | **High** | Author minimal AWS IaC (VPC, RDS PostGIS, ElastiCache Redis, ECS Fargate, S3) and gated `deploy-production.yml` with rollback. | Solo Dev | `DIR-055`, `DIR-056` |
| **RISK-012** | Operations | **No Backup / Restore or Load Verification**: RDS automated snapshot restore and k6 concurrency targets have never been tested. | Medium | High | **High** | Run k6 load tests against Staging and execute documented DB backup/restore drill prior to Release 0.9 RC. | Solo Dev | `DIR-050`, `DIR-059` |
| **RISK-013** | Trust & Safety | **PII / Doxxing & Hinglish Abuse Bypass**: Current `ModerationService` uses basic regex/keyword lists; Hinglish harassment or regional PII formats could slip through. | Medium | High | **High** | Expand Indian PII regexes (Aadhaar, PAN, UPI, phone variants), Hinglish/vernacular lexicon, auto-hold thresholds, and moderation SOPs. | Solo Dev | `DIR-040`, `DIR-061` |
| **RISK-014** | Delivery | **Solo Developer Capacity & Context-Switching**: Maintaining NestJS API, Expo Mobile/Web, Next.js Admin, and AWS infra simultaneously creates bottleneck risk. | High | Medium | **Medium** | Enforce strict 15–18 SP/sprint velocity cap, prioritize P0/P1 security & contract alignment first, defer P2/P3 enhancements post-MVP. | Solo Dev | `DIR-EP01`–`DIR-EP15` |
| **RISK-015** | Legal / Compliance | **Indian DPDP Act & CERT-In Readiness**: Lacks formal Privacy Policy, Terms of Service, consent versioning enforcement, and 6-hour/72-hour incident & LEA escalation runbooks. | Medium | High | **High** | Publish `docs/legal/` DPDP & Trust/Safety SOPs, enforce `UserConsent` version checks on onboarding, and test data export/erasure. | Solo Dev | `DIR-061` |
